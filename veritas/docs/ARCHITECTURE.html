VERITAS

AI Truth Encyclopedia — System Architecture
v1.4 · June 2026
Stack: Go + Python + MongoDB + Next.js · Port 4097 · Zero-infrastructure mock mode

1. What Veritas Is

Veritas is a knowledge construction engine — it produces structured, evidence-grounded encyclopedia articles. It is not a chatbot, not a summarizer, not a Wikipedia scraper. It actively seeks out evidence across all truth categories (confirmed, contested, suppressed, speculative), surfaces what has been buried, and exposes the linguistic and structural mechanisms by which information is distorted.

The system is built around a strict three-layer epistemic separation that prevents cross-contamination between evidence detection, interpretation, and synthesis. Each layer has typed I/O contracts, enumerated permissions, and hard prohibitions — enforceable at the code level.

Core epistemic commitment: Organized suppression of information by powerful institutions is a documented historical reality. A knowledge system that does not model the absence of evidence as a meaningful signal will silently reproduce the gaps created by that suppression. Veritas refuses to be that system.
3Strict Layers

Evidence Integrity → Epistemic Analysis → Knowledge Construction. No layer can do another's job.

9Pipeline Nodes

Stateless Python workers in a DAG, JSON-in/JSON-out subprocess bridge with mock fallback.

14Agent Tools

Built into the native Go agent: web search, article CRUD, image gen, citation verification, sub-delegation.

23Storage CRUD ops

Articles, conversations, users, jobs, maps, graph edges, memory KV — MongoDB with in-memory mock mode.

2.1 Layer 1 — Evidence Integrity (Python)

PermissionsDetect evidence presence/absence (binary), tag type (enumerated), classify uncertainty (verified_gap / unverified_gap / false_positive_risk), retrieve from all truth categories (confirmed / contested / suppressed / speculative), tag chain of custody and acquisition method
ProhibitedAssign causality to absence ("Gap ≠ suppression"), interpret meaning of a gap, correct euphemisms, score source credibility, infer intent
Nodesretrieve.py — Retrieves evidence across all 4 truth categories + web search
extract_claims.py — Parses into atomic, source-traceable statements
map_evidence.py — Links claims to supporting/contradicting evidence with gap metadata

2.2 Layer 2 — Epistemic Analysis (Python)

PermissionsInterpret evidence quality, flag structural patterns, map language framing, assign confidence scores — all outputs must be labeled is_interpretive: true
ProhibitedAssigning causality without external metadata from Layer 1, stating interpretive outputs as facts, replacing original language
Nodescritique.py — Multi-factor evaluation (factual consistency, source reliability, reasoning validity)
detect_missing.py — "Dogs that didn't bark" — structural gaps with cause labeling only when external metadata exists
map_language.py — Euphemism/framing detection, dual output (original + precision upgrade)
scrutinize.py — Structural risk factors (collective attribution, single-source dependency, coercion indicators)

2.3 Layer 3 — Knowledge Construction (Go + Python)

PermissionsSynthesize, narrate, resolve contradictions, compute final confidence vectors, generate articles, run the agent tool loop
ProhibitedRe-inventing evidence structure, introducing new claims not traceable to Layer 1 evidence, dropping provenance
Nodesresolve.py — Integrates all Layer 2 analyses, resolves contradictions, computes 6-dimension confidence vectors
generate_article.py — Synthesizes the final structured article from resolved claims
store.py — Structural placeholder (Go handles actual persistence)
AgentNative Go agent loop (25 iterations, 14 tools, 90k token budget, SSE streaming)

4. Python Workers

Each of the 9 epistemic nodes is a standalone Python script under python-workers/nodes/. They share a common LLM client and system prompt. The Go orchestrator spawns them as subprocesses via nodes.RunPythonNode, passing JSON on STDIN and reading JSON from STDOUT.

4.1 LLM Client

llm/client.py provides a provider-agnostic LLMClient.invoke(system_prompt, user_prompt) -> dict. It tries providers in configured order and falls back gracefully:

4.2 System Prompt

veritas_prompt.py loads the canonical prompt from shared/system_prompt.txt (with a Go-side fallback in veritas_prompt.txt). The prompt enforces: every claim traces to a specific source, distinguish evidence types, mark weak/speculative when evidence is thin, no intent inference, expose gaps.

5.1 DAG Engine (internal/dag/engine.go)

  • Validation: DFS-based cycle detection. Checks all DependsOn references exist. Returns error immediately if the graph is invalid.
  • Concurrency: Single goroutine polls every 50ms to decide which nodes are ready (all deps met, not yet started). Each ready node fires in its own goroutine. No max concurrency limit — all parallel-ready nodes execute simultaneously.
  • Retry: Per-node RetryPolicy{MaxAttempts, BackoffBase, BackoffMax}. Linear backoff: attempt * BackoffBase, capped at BackoffMax. Context cancellation checked between retries.
  • Progress: Channel-based (chan ProgressUpdate, buffered 16) with events for running, completed, failed.
  • Timeouts: Per-node Timeout wraps execution in context.WithTimeout. Workflow-level timeout of 5 minutes.

5.2 Phase Mapping

5.3 Generation Queue

internal/api/queue.go — bounded in-process worker pool (maxWorkers = 3, channel buffer 128). Ensures at most 3 concurrent generation jobs. Deduplication prevents concurrent generation of the same slug. Crash recovery via Restore() on server start. Never call processArticle directly from a request handler — always enqueue via s.queue.Submit(slug, persona).

6.3 Context Management

When the accumulated conversation exceeds 360k characters:

  1. Pass 1: Truncate every RoleTool.Content to 200 chars + "\n...[truncated]" — preserves the structure of assistant↔tool exchanges.
  2. Pass 2 (if still over budget): Drop the oldest complete "tool-conversation unit" (assistant message with tool_calls + all trailing RoleTool messages). Never drops the seed user message (index 0).

6.4 Abort Mechanism

Three abort paths: client disconnect (r.Context().Done() triggers via goroutine in chat.go), HTTP stop endpoint (POST /chat/:id/stop), or agent internal check. Abort is goroutine-safe via sync.Mutex. Checked at iteration start and before each tool goroutine. On abort, returns whatever text was accumulated.

6.5 LLM Provider Routing (Go)

The Go agent's LLM client (internal/agent/llm.go) routes models to two OpenAI-compatible providers. The default chat model was switched from deepseek-4-flash (DigitalOcean Inference, no API key set) to llama-4-scout-17b-16e-instruct on Groq (API key configured, 5-10x faster):

ModelProviderRole
llama-4-scout-17b-16e-instructGroqDefault chat — fastest available provider with configured API key
gemma-4-31B-itDigitalOcean InferenceReasoning tasks (no API key set — will fall through)
deepseek-4-flashGroq / DO InferenceFast chat fallback
deepseek-v4-proDigitalOcean InferenceReasoning (no API key set)

Retry policy: 3 attempts, exponential backoff (initial 1s, max 4s), per-attempt timeout 120s, overall 300s timeout. If a provider key is unset or fails, the client iterates to the next configured provider.

7.2 Mock Mode

Enabled when MOONGOSE_CONNECTION_STRING is empty OR MongoDB connection/ping fails (internal/storage/db.go:147). In-memory maps for users, conversations, messages. 8. Streaming & SSE

Veritas uses server-sent events (SSE) for all real-time communication. There are two independent SSE paths:

8.1 Chat Stream (/chat/:id/messages)

The agent's OnEvent callback emits AgentEvent structs that get serialized as SSE data: lines. Events include:

Event TypeInner TypeEmitted WhenData
agent_eventtextStreaming text delta from LLMPartial text content
agent_eventtext (final)Final assistant text (no tool calls)Full text content
agent_eventtool_useBefore tool execution{name, args}
agent_eventtool_resultAfter tool execution{name, truncated_result}
agent_eventtraceAfter each LLM call{iteration, latencyMs, usage}
agent_eventdoneAgent run complete{msgId, content, blocks[]} — structured block array for rich rendering

The SSE writer in internal/api/chat.go uses http.Flusher with panic recovery (defer/recover()) so streaming connections terminate cleanly even if the client disconnects.

Known fix — SSE flushing: The logWriter wrapper in internal/api/server.go didn't implement http.Flusher, causing a 500 "Streaming unsupported" error from the corsHandler wrapper. Fixed by delegating Flush() to the underlying http.ResponseWriter.

8.2 Article Progress (/articles/:slug/progress)

BroadcastProgress (internal/api/handlers.go) fans events to all subscribers on a slug's channel via a map[string][]chan string protected by sync.RWMutex. Events include:

EventEmitted WhenData
progressEach DAG node starts/completes/fails{slug, phase, node, status, timestamp, error?}
article_completeFull pipeline finishes{slug, article_id, title, derived_confidence, timestamp}
heartbeatEvery 15s during generation{timestamp}

8.3 Frontend Integration

packages/web/src/app/hooks/useChatStream.ts parses SSE data: lines from the chat endpoint. ProcessViewer.tsx and GenerationBar.tsx render live tool activity and phase progress from the article generation stream.
