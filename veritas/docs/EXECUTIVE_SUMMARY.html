Truthseekers is a knowledge construction engine that produces structured, evidence-grounded encyclopedia articles — not chat summaries, not Wikipedia mirrors. It actively surfaces evidence across all truth categories (confirmed, contested, suppressed, speculative), exposes framing and structural distortion, and refuses to treat the absence of evidence as silence.

The Problem

Every knowledge platform today has the same architecture: a chatbot with a search query. The result is a summary — fluent but flat, confident but shallow, unable to distinguish between consensus, controversy, and deliberate suppression. Wikipedia, the gold standard, is a political instrument with gatekept narratives. LLMs amplify the problem: they reproduce the most statistically common framing, which is the establishment framing.

Conventional systems cannot:

  • Distinguish evidence quality from narrative fluency
  • Detect missing evidence as a meaningful signal
  • Separate factual claims from framing/language choices
  • Trace provenance from final article back to source passages
  • Assign multi-dimensional confidence (not just "this is true")
  • Surface suppressed or contested evidence alongside consensus

Truthseekers does all six, by design:

  • Strict three-layer epistemic separation — evidence, analysis, construction never mix roles
  • Gap detection as a first-class epistemic signal — "dogs that didn't bark"
  • Dual-output language mapping — original framing preserved alongside precision upgrade
  • Atomic claim graph with full provenance chains
  • Six-axis confidence: evidence strength, corroboration, source diversity, recency, contradiction level, bias risk
  • Four truth categories: confirmed, contested, suppressed, speculative — all retrieved

Go Backend

Zero-framework net/http API gateway on port 4097. Native agent loop, DAG engine, Python subprocess bridge, MongoDB with in-memory mock mode. Graceful shutdown, CORS, HMAC JWT auth. stdlib only

Python Workers

9 stateless epistemic nodes. Each is a standalone script, JSON-in/JSON-out over STDIN/STDOUT. Shared LLM client with 4-provider fallback chain. Mock responses when no API key is set. subprocess bridge

Next.js Frontend

React 19, Framer Motion, TanStack Query, Tailwind CSS. Editorial design with antique gold & ink aesthetic. Structured block renderer, SSE streaming chat, 3D map viewer, interactive timeline, Mermaid.js diagrams. live data

Zero Infrastructure

Full local development with no external dependencies. Mock MongoDB, mock Python workers, mock web search. Meaningful demo from go run ./cmd/server alone. No Docker, no cloud account required. zero-infra mode

Technical Differentiation

Strict Epistemic Layers

Three layers with typed I/O contracts, enumerated permissions, and hard prohibitions enforceable at code level. Layer 1 detects evidence but cannot assign causality. Layer 2 interprets but must self-label as interpretive. Layer 3 synthesizes but cannot introduce new claims.

Claim Graph Architecture

Claims are first-class objects with full provenance chains. Articles are generated views over an atomic claim graph. Every assertion traces to a source passage. Six-axis confidence vectors replace scalar "confidence scores."

Gap Detection

detect_missing.py identifies structural evidence gaps — "dogs that didn't bark." Absence is a meaningful epistemic signal, not silence. Gaps are labeled by type and verification status, with cause attribution only when external metadata exists.

Language Mapping

map_language.py detects euphemism, framing, and linguistic distortion. Outputs dual-channel: original language preserved alongside precision upgrade. "Collateral damage" maps to "civilian deaths." "Enhanced interrogation" maps to "torture." No information lost.

Multi-Provider LLM Routing

Four fallback providers in Python workers (Groq → DO Inference → NVIDIA NIM → OpenAI), two in Go agent (Groq + DO Inference). Deterministic temperature: 0 structured output, json_object response format. Graceful degradation when keys are missing.

Zero-Infra Mock Mode

Every external dependency has a mock fallback by design. No MongoDB? In-memory mock. No Python? Mock node responses. No API keys? Mock LLM responses. go run ./cmd/server starts a fully functional server with valid-looking output.

Technology Stack

Backend

  • Language: Go 1.22+, stdlib net/http — no web frameworks
  • Storage: MongoDB (go.mongodb.org/mongo-driver) + in-memory mock
  • Auth: HMAC-SHA256 JWT (dev), unsigned in practice
  • LLM: OpenAI-compatible API (Groq + DigitalOcean Inference)
  • Workers: Python 3.11+ subprocesses, JSON over STDIN/STDOUT
  • Concurrency: Goroutines + sync.WaitGroup for tool execution, polling loop for DAG

Frontend

  • Framework: Next.js 15.5.19, React 19
  • Styling: Tailwind CSS 4, CSS custom properties
  • State: TanStack Query (server state), React state (UI state)
  • Animation: Framer Motion 11.x
  • Charts/Maps: Mermaid.js, Leaflet (2D maps), React Three Fiber (3D)
  • Streaming: Native fetch + SSE parser
Key decision — no framework: The Go backend uses zero web frameworks. No Gin, no Chi, no Echo. Routing is hand-dispatch on http.ServeMux. This is deliberate — the API surface is small and stable, and framework removal reduces attack surface, build time, and dependency risk. The entire orchestrator compiles in <10 seconds.
